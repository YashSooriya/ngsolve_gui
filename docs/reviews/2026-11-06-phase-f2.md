# MagMechSim Phase F2: Engineering Workflow Refinement and Legacy Retirement

**Date:** 6 November 2026  
**Status:** Complete for the documented and tested scope; awaiting independent review  
**Application:** Full MagMechSim packaged Windows application (`0.2.8.dev319`)  
**Review package:** `MagMechSim-PhaseF2-Review-2026-11-06.zip`

## Summary

Phase F2 retired the stripped Mike edition from active source, launch, build and test workflows, while preserving MagMechSim's shared solver and file compatibility. It also corrected the most consequential workflow problems observed in the packaged application: an invalid 3D study action looked enabled, and a process that exited successfully could be presented as a scientifically complete run even when the coupled solver had not converged. Axisymmetric frequency-sweep results now preserve the solver's per-frequency convergence data in their run manifests.

No finite-element formulation, numerical algorithm, solver dependency or project schema changed. The milestone did not attempt a broad interface rewrite or a post-processing redesign. No large 3D solve was run.

## Changes and design decisions

### Legacy retirement

The old stripped package contained 42,907 files and 2,082,185,938 bytes. The archive preserves the source repository layout, the Mike-only builder and smoke verifier, the icon asset, and the old standalone package under the existing `deletable` directory. The archive manifest records original paths, sizes and reasons. No uncertain or shared solver files were moved.

The active source has no Mike-only launcher, builder, package target, CI job or application branch. Historical reviews and the living roadmap retain the name only to document prior behavior and its retirement. The separate stripped package remains in the archive for the user to inspect or remove manually.

### Workflow and status behavior

- The 3D study action is now disabled when current model validation says required material assignments are missing, instead of looking like an available primary action.
- Run-history status now pairs execution completion with the scientific result. Older manifests that lack scientific status explicitly say `Execution finished · numerical status unavailable`.
- The axisymmetric runner now derives and stores each sweep point's convergence status from the solver's returned iterations, residuals and configured tolerance. It also records iteration limits and mesh size. No numerical algorithm was changed.
- Live and saved axisymmetric history use the same status vocabulary as 3D. A successful process exit no longer implies a converged solve.
- Escape dismisses the axisymmetric geometry-creation 3D preview without applying an action to the sketch underneath.

The work remained within existing ngapp navigation, model tree, properties, run-history and packaged-desktop patterns. Axisymmetric sketch controls and the 3D OCC/wire-trace model remain separate where their engineering meaning differs.

### Small 3D coupled runs

The packaged end-to-end test imported the test STEP project and ran on a bounded 79-tetrahedron mesh:

- First run: execution `complete`, scientific status `converged`; 50 Hz, two coupling iterations, ΔA `2.34e-11`, Δu `7.51e-7`, tolerance `1e-4`. It computed a DC field with 528 H(div) coefficients and verified the saved field against the exact mesh/input fingerprints.
- Second run: execution `complete`, scientific status `nonconverged`; strict maximum of two iterations and tolerance `1e-8`. The manifest recorded `maximum_iterations_reached`, and the exact compatible DC field was reused. The application continued to show the model workspace and presented `Execution finished · not converged` in run history.
- A fresh packaged process reopened the project with coupled physics, frequency, source, DC field and iteration/tolerance settings preserved.
- The run-history row displayed both the per-frequency diagnostic and the process/numerical status. The Results navigator showed the generated field entries; no post-processing redesign was attempted.

These bounded runs verify configuration propagation and status handling for this test model. They do not establish broad predictive accuracy for coupled 3D engineering models.

### Axisymmetric frequency sweep

The packaged `Getting started - coupled coil` example completed two frequencies on a 579-element mesh with 2,410 degrees of freedom. The 250 Hz point converged in three iterations (ΔA `1.20e-15`, Δu `3.01e-13`); the 500 Hz point converged in two iterations (ΔA `3.94e-10`, Δu `4.51e-7`). Both used tolerance `1e-6`. The solver wall time recorded in the manifest was 1.53 s. The test verified per-point manifest diagnostics, run-history status, project snapshot persistence and output files.

### Geometry and actual desktop rendering

The latest packaged F1 workflow started both 3D and axisymmetric projects, checked 3D model/property navigation and validation, selected axisymmetric geometry through native mouse input, and opened the actual geometry-creation 3D preview. The preview had two WebGL `mesh3d` traces (740 and 728 vertices), a 2576×1704 backing canvas for a 1288×852 CSS viewport, no lost context, and 4,226 contrast pixels in the sampled native window region. ## Remaining limitations and recommendation

- The blank axisymmetric preview frame was observed once and not reproduced by three later packaged checks. Its cause remains unknown.
- WebGPU exposes an API object but no adapter/device in the VirtualBox graphics environment. The geometry-creation preview used WebGL successfully. Physical Windows GPU and driver behavior remains a release-stage check.
- Coupled numerical evidence is deliberately bounded to a 79-element model and should not be treated as broad validation.
- Full historical tests and a full post-processing/results-viewer review were out of scope. The Results workspace and run-history navigation were exercised; no results UI redesign was made.
- The VM now runs from an SSD. Startup/solver timing is reported as measured, not credited to a code change.

**Recommendation:** Phase F2 is ready for independent review for its tested scope. Review the single-variant cleanup, per-frequency axisymmetric status evidence and packaged desktop screenshots before approving Phase G. Do not begin Phase G automatically.

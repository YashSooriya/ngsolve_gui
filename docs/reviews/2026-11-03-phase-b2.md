# MagMechSim Phase B2 closeout

**Date:** 3 November 2026  
**Status:** Complete for the supported single-physics workflows tested here; stopped for independent review  
**Next requested milestone:** Phase C, 3D DC magnetic background-field integration

## Summary

Phase B2 adds UI configuration for the 3D time-harmonic EM and mechanics conditions already supported by the solver. Engineers can select named CAD faces or volume regions, edit the applicable condition/source properties in the contextual inspector, and save/reopen the project without losing those stable assignments.

The work did not add fully coupled magneto-mechanics or new finite-element methods. The NGSolve changes are narrow input adapters: they pass scoped source/load values to existing assembly paths, apply current phase to the existing wire-trace source, and record the resolved settings in solver manifests. No numerical dependency or project format changed.

## Architecture and source references

- [`three_d_workspace.py`](../../src/ngsolve_gui/three_d_workspace.py): contextual study/selection inspector, editable vector phasors, active-physics controls and tree-to-property selection (`_rebuild_properties`, `_set_assignment_vector_component`, `select_item`).
- [`three_d_project.py`](../../src/ngsolve_gui/three_d_project.py): project archive validation and serialization of stable domain/boundary IDs, tags, conditions, suppression state and complex input vectors.
- [`three_d_solver.py`](../../src/ngsolve_gui/three_d_solver.py): active-assignment validation and conversion into solver inputs (`_active_boundary_assignments`, `_domain_phasor_assignments`, `build_time_harmonic_em_problem`).
- Solver [`run_gui_3d_model.py`](../../../ngsolve-ui/coupled_solver/scripts/run_gui_3d_model.py): writes resolved condition/source configuration and source mode to run provenance.
- Solver [`winding_current_source.py`](../../../ngsolve-ui/coupled_solver/src/_3D/EM/winding_current_source.py): multiplies the existing trace-current source by its complex phase; phase zero preserves the former source.
- Solver [`bilinear_and_linear_forms_3D.py`](../../../ngsolve-ui/coupled_solver/src/_3D/common/bilinear_and_linear_forms_3D.py): accepts a material-scoped body-force map and per-boundary spring stiffness maps while retaining scalar and coefficient-function inputs used by independent solver clients.

The solver modifications are small adapters around existing formulation code. They do not replace mesh assembly, weak forms, finite-element spaces, solver algorithms, or dependencies. The project schema remains backward compatible.

## Numerical and workflow verification

All numerical runs were bounded to 10 mm STEP blocks at coarse mesh size; no large 3D simulation was run.

1. **Domain current density:** a real NGSolve case ran at 50 Hz, `p=1`, with `Jz = 1e6 A/m²` and `90°`, then repeated with `2e6 A/m²`. Both manifests completed; the sampled magnetic field was finite and nonzero, and the relative difference from exact two-times scaling was below `1e-5`. The effective complex-domain source was recorded in the solver configuration.
2. **Mechanics loads and supports:** a 50 Hz, `p=1` mechanics case used a scoped `1e8 N/m³` X body-force phasor at `90°`, `ux = 1e-6 m` at `90°`, one spring face (`2e8 N/m³` normal, `5e7 N/m³` tangential), and one fixed face. The manifest retained all mapped inputs; constrained imaginary displacement matched `1e-6 m` within `1e-6` relative tolerance and the constrained real component stayed below `1e-12 m`.
3. **GUI run handoff:** the GUI-driven 10 mm EM test configured a 3,157-element mesh, `63 Hz`, `p=2`, `1.5` model-span air padding and a wire-trace source, then completed two consecutive runs from the study workflow. Both manifests were `complete`, separate solver PIDs/output directories were used, the result fields loaded, and run configuration propagated. The sampled AC magnetic flux density was `3.75990629785e-6 T` at `(0.02, 0.02, 0.02) m`.

The packaged desktop test deliberately did not solve the 22,132-element STEP fixture. It exercised its geometry, mesh display, selection, B2 controls and save/reopen workflow only. The small NGSolve runs above provide the numerical checks.

## Limitations and follow-up

- External surface traction, contact, nonlinear material/structural behavior, coupled magneto-mechanics, DC background fields and ROM are not available.
- Global Cartesian axes are used for the current vectors/displacements; selectable local coordinate systems were not added.
- The current packaged desktop check configured and persisted conditions but did not launch a solver from the imported 22,132-element CAD model. Small numerical cases and a separate GUI-driven 3,157-element run verified the solver paths without loading a large 3D workload on this PC.
- The headless GUI-run test logs WebGPU renderer errors when entering or tearing down parts of the post-processing workspace, and a screenshot-enabled diagnostic could not locate the results property-panel title. The actual packaged preprocessing displays and controlled renderer recovery passed; post-processing visualisation is outside this milestone and should be investigated separately if it recurs in normal desktop use.
- Historical Chromium memory growth remains monitored; this bounded milestone did not repeat long-session or large-model memory stress.
- The VM had moved to an SSD before the current startup and render measurements. No code attribution is made from timing comparisons.

## Summary

Phase D1 connects the existing 3D DC, time-harmonic electromagnetic and mechanical blocks into one GUI-configured coupled run. The runner computes a DC field when no exact reusable field is available, stores its H(div) coefficients with mesh and input identity, and reuses it only after validation. The existing block Gauss-Seidel and Anderson iteration remains the numerical method. The UI and job manifest now distinguish numerical convergence from process completion.

A real maximized packaged Windows app completed one coupled run and a subsequent deliberately nonconverged run using a 79-element 10 mm STEP block. The run inputs were 50 Hz, applied DC Bz = 0.025 T, AC Jx = 1e6 A/m², one fixed mechanical face, polynomial order 1, a 12-iteration limit and 1e-4 relative tolerance. The first run converged in two iterations. The second was limited to two iterations with a 1e-8 tolerance and was correctly reported as diagnostic, nonconverged output. The project was saved and reopened in a fresh packaged process with the settings preserved.

This is bounded integration evidence, not validation of predictive accuracy for arbitrary real components. A separate manufactured coupled 3D baseline passes under its existing 1% error thresholds. The realistic UI model has not been compared against an independent closed-form coupled reference or a systematic p/h refinement study.

## Existing solver architecture and implementation

The core already had a 3D time-harmonic fixed-point solver. It performs the existing electromagnetic and mechanical block sequence, updates the coupled state, uses Anderson acceleration where configured, and calculates relative A and displacement change residuals. D1 retained that formulation and its dependencies.

The changes are confined to the GUI adapter and safe state transfer:

- The GUI validates coupled study inputs and builds the existing EM, DC and mechanics problem dictionaries. Coupling activates the backend’s existing kCoupCoef/cCoupCoef terms and material, source and support maps. See ngsolve_gui/src/ngsolve_gui/three_d_solver.py, especially lines 366-438, 982-1018 and 1093-1186.
- The 3D runner identifies reusable DC fields using the DC input fingerprint, polynomial order and the saved mesh. It loads candidates through the strict mesh-aware field loader; corrupt, stale or unreadable candidates are skipped. A valid cached mesh object and its coefficients are passed to the solver. See ngsolve-ui/coupled_solver/scripts/run_gui_3d_model.py, lines 39-92, 158-210 and 319-390.
- The core entry point now accepts optional saved real H(div) coefficients, rejects use outside 3D, a simultaneous DC solve, non-finite data, or a coefficient count that does not match the active H(div) space. It creates the GridFunction in that current space. See ngsolve-ui/coupled_solver/main.py, lines 83-84 and 266-291.
- The existing solver now returns its already-calculated fixed_point_converged boolean array to the caller. The fixed-point method and equations were not changed. See ngsolve-ui/coupled_solver/src/_3D/common/time_harmonic_solver_3D.py, lines 178, 536 and 713.
- The runner sets the existing FullyCoupled sequence, Anderson depth 3 and configured iteration/tolerance values. It retains output fields on nonconvergence and writes scientific status separately from process status. The app displays the nonconvergence message and leaves the model workspace active. See ngsolve_gui/src/ngsolve_gui/app.py, lines 2850-2895 and 2969-2993.
- Coupled study controls are integrated into the existing study property editor and readiness validation. See ngsolve_gui/src/ngsolve_gui/three_d_workspace.py, lines 680-731 and 3725-3824.

The solver-side patch is small relative to the adapter: 29 lines in main.py validate and inject saved coefficients, 223 lines in the GUI runner cover field-cache provenance and status handling, and three lines expose the existing convergence flag. No finite-element formulation, coupling equation, solver dependency, or project format was changed. The solver remains runnable independently through its existing Python entry points. No Mike-variant files were changed.

## Limitations and remaining risks

- Only one 50 Hz frequency was used for the packaged coupled run. Coupled frequency sweeps and richer study scheduling are not exposed in D1.
- The actual application model is a single 10 mm block with p=1 and 79 elements. It validates integration and state propagation, not engineering accuracy for complex multibody parts.
- The manufactured-solution test is an independent analytic correctness baseline for the existing coupled formulation, but its errors are not an independent reference for the packaged STEP block. A broader coupled response/reference and practical mesh/order convergence study remain appropriate before making broad predictive-accuracy claims.
- The available material laws remain those already supported by the backend, including linear isotropic material parameters. Nonlinear B-H curves, hysteresis, contact, and other unsupported physics remain out of scope.
- The run emits an existing NGSolve H(curl) keyword-flag deprecation warning. It did not prevent solution completion and was not changed speculatively.
- The white first-frame issue is monitored, not fixed: two observed first frames were visible, but the earlier intermittent blank capture has not been root-caused.
- Historical Chromium memory growth remains a monitored Phase A risk. This milestone used only bounded, small workloads.
- No full repository test suite was run; the focused suites above cover the changed workflow and representative axisymmetric paths.

## Recommendation

Phase D1 is ready for independent review for the tested supported scope. Do not start Phase D2 until this package is accepted. The next stage should refine the coupled run summary and stale-DC state visibility, add bounded coupled reference and mesh/order checks, and improve diagnostics for convergence limits and invalid setup without changing the solver equations. Keep frequency sweeps and other advanced analysis options disabled until their UI and numerical verification are complete.

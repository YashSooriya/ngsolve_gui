# MagMechSim Phase B1 Review

**Date:** 3 November 2026  
**Status:** Complete for the bounded Phase B1 scope; stopped before Phase B2  
**Application:** Full MagMechSim, not the separate stripped Mike variant

## Summary

Phase B1 adds a usable 3D geometry and material-preparation workflow around the existing stable STEP solid identities and solver adapter. Engineers can inspect and rename STEP solids in the model tree, assign materials, create reusable named-domain selections, isolate/show solids, edit a reusable material library, and identify invalid material values. A selected solid now receives a visible orange CAD-face outline in the 3D viewport.

Geometry and material changes remain in the existing 3D project representation. The UI propagates physical material coefficients to the existing NGSolve input dictionaries; a zero-conductivity solid is represented as an insulating domain. The numerical solver algorithms and dependencies were not changed, and no project schema migration was introduced. Small EM and mechanics-only runs verified the adapter against the real solver.

## Architecture and implementation

- The work extends the existing `ThreeDWorkspace` and its model tree, property editor, mesh cache and preview. It does not replace the STEP or wire-trace workflows. Solid rows use the existing stable STEP domain tags. See [`three_d_workspace.py`](../../src/ngsolve_gui/three_d_workspace.py#L111), the solid tree and assignment methods at lines 1402–1420 and 2178–2310, and preview selection handling at line 3394.
- Per-solid material assignment and user-created named-domain selections continue to use the existing project structures and CAD assignment-recovery path. A project reopen restores body names, material snapshots and named selections; changed STEP topology marks affected assignments `Needs review` and offers user-guided reassignment instead of silently attaching to new entities.
- The reusable material store is a small JSON-backed `MaterialLibrary` in the existing per-user settings area; project files continue embedding the materials they use. The editor supports relative permeability, electrical conductivity, Young's modulus, Poisson's ratio and density with their existing physical units. Built-ins remain protected; user materials can be created, duplicated, edited and removed.
- [`three_d_solver.py`](../../src/ngsolve_gui/three_d_solver.py#L37) validates properties required by the active single-physics formulation and supplies neutral values for inactive coefficients expected by the existing solver interface. The adapter maps material values into `murdict`, `sigmadict`, `Edict`, `nudict` and `rhodict`; `inoroutdict` now follows conductivity so `sigma = 0` is insulating. No constitutive model beyond the backend's current linear properties is offered.
- [`material_library.py`](../../src/ngsolve_gui/material_library.py#L8) isolates persistent presets from project snapshots. The updated [`boundary_overlay_trace`](../../src/ngsolve_gui/three_d_preview.py#L275) can preserve each selected solid face's perimeter. This prevents shared edges of a closed solid from cancelling in the union outline; boundary selections retain their perimeter-style highlighting.

### Packaged desktop workflow

The installed full MagMechSim package was operated through the reusable Windows harness, not Codex Computer Use. Win32 `SendInput` performed actual mouse and keyboard input; Pillow `ImageGrab` captured the full Windows desktop; Playwright attached through test-only loopback CDP for read-only DOM/Plotly inspection. The app was maximized for the entire workflow. The workflow harness produced 21 **1920 × 1094** full-desktop captures. A separate smoke run through the workstation launcher produced one additional full-desktop capture, for 22 screenshots in the review ZIP.

The three fresh launches exercised:

1. The splash-to-maximized-workspace transition, opening the seeded two-body STEP project, meshing, body selection and orange viewport outline.
2. Material assignment and editing, negative-conductivity rejection, body isolation/show-all, save and close.
3. Reopening the saved project, remeshing, then replacing the STEP geometry with changed topology and verifying stale named selections are flagged for review.

The test mesh contained **24 surface triangles, 18 vertices and 24 boundary regions**. Selecting a solid produced a visible orange overlay with 36 non-null coordinate points. Isolation reduced the visible triangles from 24 to 12, and “Show all solids” restored all 24. The custom material snapshot persisted with `μr = 1`, `σ = 3.4e6 S/m`, `E = 110e9 Pa`, `ν = 0.34` and `ρ = 8960 kg/m³`. The invalid edit was rejected and cancelled without replacing the saved material. Reopen restored the `Rotor body` name, stable domain tag, Copper assignment, `Phase B1 Alloy` assignment and `Rotor conductor` named domain selection. After CAD topology changed, both affected selections displayed `Needs review`; no old tag was silently reused.

### Numerical integration evidence

The bounded 10 mm cube EM case used **79 volume elements**, **337 degrees of freedom**, first-order discretisation and **50 Hz**. The solver manifest completed successfully in approximately **0.35 s**. At probe `(0.0025, 0.005, 0.005) m`, the computed `|B|` was `3.93819477475e-05 T` with `σ = 1.4e6 S/m` and `3.93819863335e-05 T` with `σ = 0`; the difference was `3.858600e-11 T`. The run also verified that the zero-conductivity coefficient and insulating-domain flag reached the generated solver configuration. This is evidence of propagation and response in a bounded case, not an independent convergence or broad numerical validation study.

The mechanics-only case used **12 volume elements** and exported a nonzero maximum displacement of `2.24128e-08 m`. The test log includes solver manifests and the NGSolve deprecation warning about the existing `flags` argument; the run passed.

### Performance observations

The native harness reported splash-to-ready times of **13.633 s**, **8.181 s** and **7.636 s** across the three launches. Opening the seeded project took about **7.17 s**; rendering its coarse 24-triangle mesh took **2.17 s**. These values are observations for this VM and small fixture, not performance targets or a controlled before/after comparison. The VM had moved to an SSD before this milestone, so storage is a confounder. This work did not repeat Phase A's broader renderer-memory investigation; the historical Chromium memory concern remains monitored, not a blocker.

## Limitations and next milestone

This closes Phase B1's geometry organisation, material definition/assignment, persistence and safe-recovery scope. It does not complete the broader 3D engineering workflow: supported 3D boundary conditions, sources, vector directions and mechanical loads remain for **Phase B2**. DC background-field and fully coupled magneto-mechanics remain later phases. The native geometry sample is deliberately small; responsiveness on larger multibody STEP assemblies and long-session memory have not been benchmarked here. No comprehensive all-repository test suite was run; the listed focused groups target the changed functionality and compatibility paths.

**Recommendation:** B1 is ready for independent review. After review, the next coherent milestone is Phase B2: expose the already supported 3D electromagnetic and mechanics boundary-condition, source and load workflows through the UI and verify each setting reaches the real solver. Stop here; do not begin B2 automatically.

# MagMechSim Phase C closeout

**Date:** 3 November 2026  
**Status:** Complete for the verified DC scope; stopped for independent review  
**Next milestone:** Phase D, fully coupled 3D magneto-mechanical harmonic analysis  
**Application:** Full MagMechSim; the separate Mike variant was not changed

## Summary

Phase C adds a `Static/DC magnetics` study to the existing 3D model workflow. The study uses the existing NGSolve `solveBDC_3D` formulation, accepts a uniform applied flux density, volume current density and DC wire-trace current, and keeps the harmonic frequency control out of the DC editor. It uses the project’s assigned relative permeability and existing named geometry selections.

After a successful run, the H(div) flux-density coefficients are stored in `dc_background_field.npz`. The artifact is tied to the exact mesh hash, active DC input fingerprint and polynomial order. A changed DC input or mesh is rejected rather than silently reusing an old field. The subsequent coupled-study UI and field consumption remain Phase D work.

The production solver change is limited to orchestration, storage and one optional DC wire-trace source term: **234 added and 8 removed lines across four solver files** from the Phase B2 base. The mesh formulation, finite-element spaces, direct/iterative solve selection and dependency set were retained. The GUI change is **1,004 added and 140 removed lines across six files** for the DC study/editor, active-physics validation, source configuration and persistence. No project format migration or broad numerical rewrite was made.

## Existing solver capability and integration

The backend already had a 3D static vector-potential solve in [`solveBDC_3D.py`](../../../ngsolve-ui/coupled_solver/src/_3D/EM/solveBDC_3D.py#L5). It assembles the curl-curl operator with relative permeability, solves for vector potential A, and maps `curl(A)` to the existing H(div) space for B. Existing 3D block-Gauss–Seidel and Aitken code already reconstructs `gfBDCdata`; Phase C does not add the coupled iteration.

| Input or output | Phase C behavior |
|---|---|
| Uniform applied field | The GUI stores `dc_background_field_t` in tesla. The adapter applies `A = 0.5 (B₀ × r)` on the outer air boundary. |
| Domain current density | A real XYZ vector in A/m² is assigned to solid regions through named selections and assembled by the existing `srcdictDC` path. |
| DC wire-trace current | Existing wire-trace geometry is converted to a real Biot–Savart H source and added to the existing weak form. Focused source tests pass; this source was not part of the packaged solver run. |
| Material | Active DC validation requires finite positive relative permeability. Electrical conductivity and mechanical properties remain in the project material but are inactive in the static formulation. Nonlinear B–H, hysteresis and permanent-magnet models are not implemented. |
| Boundary and discretisation | Existing A=0 boundary assignments, air padding and polynomial orders 1–4 are passed through where applicable. Frequency is omitted for DC. |
| Saved background | Real H(div) coefficients are written atomically with schema/version, mesh SHA-256, input fingerprint, polynomial order and coefficient count. |

The GUI continues to use the existing `study.physics` state and contextual inspector. The project adapter validates only the properties required by active physics; DC requires μr and does not require harmonic conductivity or mechanical data. The actual model’s material editor retained the copper conductivity (`5.8e7 S/m`); the DC solver configuration uses a neutral zero conductivity because this formulation does not consume σ.

## Numerical evidence

These are bounded, small cases; no large 3D run was used.

### Uniform-field and material reference

For a sphere in a uniform field, the analytic interior field for a linear sphere is `B_inside = 3 μr / (μr + 2) · B₀`. With `B₀ = 0.020 T`, the μr=1 control is 0.020 T and the μr=2 reference is 0.030 T.

| μr | Maximum element size | Tetrahedra | Center Bz | Relative error to analytic field |
|---:|---:|---:|---:|---:|
| 1 | 2.0 mm | 11,915 | 0.0199999999999937 T | < 0.000001% |
| 2 | 2.0 mm | 11,915 | 0.0287751032097969 T | 4.083% |
| 2 | 1.5 mm | 23,152 | 0.0292693657914307 T | 2.435% |

The finer mesh reduced the μr=2 error by about 40%. This is one bounded h-refinement comparison at p=1; it does not establish an asymptotic convergence order. The output is from [`test_small_3d_dc_sphere_matches_uniform_field_and_permeability_effect`](../../tests/test_three_d_solver_setup.py#L1538), and the captured values are in `evidence/tests/phase-c-sphere-refinement.log`.

### Applied current direction

A separate 10 mm block used `Jz = 1e6 A/m²`, no applied background, p=1 and a 353-tetrahedron mesh. At `(0.012, 0.005, 0.005) m`, just outside the +X face, the solver returned `B = [5.5067e-5, 2.3563e-3, 1.8865e-5] T`. The dominant +Y component matches the right-hand rule for +Z current. All components were finite. See `evidence/tests/phase-c-current-density-reference.log`.

### Native packaged DC solve

The full Windows application configured and ran a 10 mm STEP block with 3,993 tetrahedra, p=1, a 2-span air region, applied `Bz = 0.002 T`, and a scoped `Jz = 1e6 A/m²`. The run used the direct solver, had 14,248 solve DOFs, completed the DC formulation in 0.68 s, and saved 25,779 H(div) coefficients. `run_manifest.json`, `problem.json`, `solver.log`, `mesh.vol` and `dc_background_field.npz` are included under `evidence/numerical/native-run/`.

The saved field was reopened against the exact mesh and inputs. A fresh application launch restored the DC project settings. Changing Bz from 0.002 T to 0.003 T changed the input fingerprint and the previous field loader rejected it with “DC inputs have changed.” This is evidence of correct execution, physical direction/magnitude behavior, material effect and artifact invalidation; the direct-solver completion alone is not presented as numerical validation.

## Known limitations and risks

- The current material law is linear and isotropic. Nonlinear B–H, hysteresis and permanent magnets are unsupported and not exposed.
- DC wire-trace source assembly has unit coverage but no packaged solver run or independent field reference in this milestone.
- The saved field is persisted and stale-checked, but Phase C does not expose downstream coupled-field reuse. Phase D must connect it to the existing coupled sequence.
- The μr=2 sphere case is coarse, p=1 and has one refinement step; this is limited numerical evidence, not a production mesh-convergence study.
- NGSolve emits an existing H(curl) keyword-flags deprecation warning during the DC run. The run completed; this warning was not addressed by a dependency change.
- One transient white frame occurred once and was not reproduced in later fresh launches. Keep the first-frame probe and investigate if it recurs in ordinary use.
- Chromium memory growth remains the previously monitored Phase A risk; it was not reopened by this bounded Phase C work.
